# 项目与群共享记忆

共享记忆保存在服务端 `stateDir` 的 SQLite 数据库中，与会话及 worktree 分开。主会话重建、归档、上下文压缩或清理执行目录不会移除这些记录；迁移机器时需要一起备份和迁移状态数据库。不会恢复已经删除且从未提取过记忆的历史会话，也不会复制整段会话上下文。

## 启用

在 **设置 → 记忆** 填入 TypeSafe API 密钥，开启共享记忆并保存；也可以在服务进程环境中设置 `TYPESAFE_API_KEY`。默认关闭。密钥只保存在服务端，不在接口响应、记忆历史或浏览器草稿中返回；输入框留空保留现有密钥。服务端数据库的访问权限与现有运行状态相同，备份中可能包含密钥。

默认模型 `jev-latest`，自动保存门槛为 `0.9`。这是模型评分，不是事实准确率，应根据团队真实样本校准。启用会将候选正文、逐字引用和相关记忆发送到 TypeSafe 的 `https://api.typesafe.ai/v1/systemone`。不需要新的数据库或 SDK。

## 保存和读取

主调度和执行会话获得三个工具：

- `orchestrator_memory_read`：按当前来源和工单权限读取相关记忆。
- `orchestrator_memory_propose`：提交简洁事实及原始人类消息或当前工单已有执行报告中的逐字引用。
- `orchestrator_memory_forget`：根据获准用户明确的遗忘指令停用指定记忆。

启用后，系统提示词要求会话在新任务或研判前读取记忆，遇到有依据的稳定约定或已验证经验时主动提交候选，无需用户每次说“记住”。提取由当前会话模型执行，Jev 负责长期价值、证据支持、归属、重复、冲突及召回相关性判断。主调度可在工单结束后使用 `ticket_id` 和 `report_id`（assignment ID）提交该工单报告中的经验，执行器不能指定别人的工单。普通代码负责来源验证、范围隔离、并发版本检查和持久化。模型可能漏提取或判断错误，来源引用并不等于外部事实核验。

项目目前对应配置中的 Git 仓库，以平台和仓库地址标识；多个群关联同一仓库时共享该项目知识。群沟通偏好保留在对应群。执行器只能访问当前工单关联的仓库与来源，不能借记忆工具读取其他工单；修改仓库绑定、停用来源或撤销用户资格会影响后续访问。同一个仓库标识改绑其他地址不会继承旧项目记忆。

跨群工具返回项目知识正文及来源标识，不返回原群消息的完整引用。管理页可查看来源引用和版本历史。记忆仅是参考，不能授予权限，也不能覆盖用户要求和仓库规则。

## 审核与失败处理

所有高分判断都通过且与现有记忆相容时自动生效；重复、临时内容和缺少依据的候选拒绝；不确定、冲突、服务失败的候选进入待确认。先持久化候选再请求模型，因此网络失败不丢失候选，也不阻止正常派工。失败候选可在管理页根据来源人工确认；第一版没有自动后台重试。

在设置页按项目、群、状态筛选，编辑正文或归属、确认生效、拒绝、停用，并查看各版本。冲突需先编辑或停用旧记忆，再确认新记忆。版本不一致时拒绝保存，保留本地草稿；可取消编辑并刷新后重新处理，避免会话间相互覆盖。确认项目记忆即允许关联该仓库的群读取正文。

“停用记忆”及工具“遗忘”停止后续召回，仍保留审计历史和原始引用，不是彻底抹除数据。旧候选再次提交不会自动复活。禁用功能停止自动读写，已有记录仍可管理。已经注入某个会话的文字无法从该会话过去的上下文中撤回。

为控制请求大小，同范围超过 40 条生效记忆时，新候选转人工确认；读取先按关键词选择最多 20 条交给 Jev，再返回最多 8 条相关结果；执行器初始化最多附带 5 条近期摘要。第一版没有向量索引，表达相差很大时可能漏召回。常见密钥模式会被拒绝，仍需避免将敏感信息提交为共享知识。

协议依据：[System One API](https://docs.typesafe.ai/api/system-one.md)、[记忆示例](https://docs.typesafe.ai/cookbooks/basic_memory.md)。
